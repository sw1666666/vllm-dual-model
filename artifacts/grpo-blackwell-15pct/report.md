# 约 15% 的 8B 路由率：单卡吞吐实验

2026-11-26，固定 GRPO 阈值为 **0.6475**。两档合成输入上，最终版 V2 的实际 8B 路由率分别为 **15.65%** 和 **15.06%**。B=128 的全部 512 个请求和 B=256 的全部 1,024 个请求均生成满 32 个 token。两个并发均保留 V2；每档 V2 三次正式计时的最低吞吐都高于同档 V1 的最高吞吐。

| 数据 / 活跃并发 | 上一版 tok/s | V1 tok/s | V2 tok/s | 纯 8B tok/s | V2 较上一版 | V2 / 纯 8B |
|---|---:|---:|---:|---:|---:|---:|
| 固定输入 / 128 | 3,251.5 | 3,887.3 | 4,159.8 | 3,226.4 | +908.3 tok/s（+27.93%） | 1.289× |
| 固定输入 / 256 | 3,837.1 | 4,754.7 | 5,123.8 | 3,658.0 | +1,286.6 tok/s（+33.53%） | 1.401× |

B=128 时，V1 清理采样热路径后较 479d6ff 提升 **19.55%**，V2 增加攒批后较 V1 再提升 **7.01%**。B=256 时两步分别提升 **23.91%** 和 **7.76%**。各版本使用相同 checkpoint、同一阈值、同一组固定输入。百分比按未舍入的吞吐中位数之比计算。

## 8B 路由与工作量

每行给出一次正式提交的计数；同组的三轮计数相同。路由占比按输出 token 统计。历史补算位置为每次命中的 `large_delta - 1` 之和；8B 总位置还包含产出当前 token 的位置。

| 数据 / B | 版本 | 8B 输出 / 总输出 | 8B 占比 | 8B 前向次数 | 历史补算位置 | 双模型路径的 8B 总位置 |
|---|---|---:|---:|---:|---:|---:|
| 固定 / 128 | 上一版、V1 | 2,556 / 16,384 | 15.60% | 132 | 28,940 | 31,496 |
| 固定 / 128 | V2 | 2,564 / 16,384 | 15.65% | 112 | 28,927 | 31,491 |
| 固定 / 128 | 纯 8B | 16,384 / 16,384 | 100% | 132 | — | — |
| 固定 / 256 | 上一版、V1 | 4,948 / 32,768 | 15.10% | 132 | 55,126 | 60,074 |
| 固定 / 256 | V2 | 4,934 / 32,768 | 15.06% | 106 | 54,689 | 59,623 |
| 固定 / 256 | 纯 8B | 32,768 / 32,768 | 100% | 132 | — | — |
| GSM8K / 96 | 上一版、V2 | 118 / 3,072 | 3.84% | 20 | 6,831 | 6,949 |

GSM8K B=96 的上一版为 **3,510.9 tok/s**，最终版为 **4,070.7 tok/s**，增加 **559.8 tok/s（+15.95%）**。两版的 3,072 个输出 token 均一致。15% 是本次合成主负载的校准目标；同一阈值用于 GSM8K，实际 8B 占比为 3.84%。

与前次阈值 0.5 的 V2 对照，B=128、256 的 8B 占比由 22.07%、21.59% 降至 15.65%、15.06%，V2 / 同轮纯 8B 从 1.088×、1.125× 变为 1.289×、1.401×。GSM8K 上则从 98 次 8B 输出变为 118 次，8B 前向由 6 次变为 20 次，V2 的吞吐从 5,206.8 降至 4,070.7 tok/s。阈值变更会改变生成历史，两个阈值下分别运行的在线策略可以产生不同的后续决策。[阈值 0.5 的结果](../grpo-blackwell-batch/report.md)

## 路由动作和 token 对齐

固定 8 条请求、每条输出 32 个 token，上一版、V1、V2 的 256 个路由动作和 token ID 逐位置完全一致。两个主测并发上，V1 三轮完整输出的摘要均与上一版一致。GSM8K 的 V2 三轮输出摘要也均与同阈值的上一版一致。

V2 改变了组批形状。计时外对两档完整合成负载分别复跑上一版和 V2，四次复跑均重现各自正式计时的输出摘要。逐次核对了 8B 实际 GPU 输入 token 与当前请求已提交的历史切片，以及大模型 KV 游标的连续性，四次均通过。

| 并发 | 有 token 差异的请求 | 至少一个动作或 token 不同的请求 | 不同 token 位置 | 不同动作位置 |
|---|---:|---:|---:|---:|
| B=128 | 11 / 512 | 11 / 512 | 210 / 16,384 | 42 / 16,384 |
| B=256 | 17 / 1,024 | 18 / 1,024 | 226 / 32,768 | 16 / 32,768 |

B=128 的首次分歧有 6 条位于小模型的 greedy 选择、3 条位于大模型、2 条位于路由判断。比如请求行 34、输出下标 15，两版都选 8B；上一版给 token 311、13 的 logits 分别为 22.75、22.734375，V2 两者同为 22.734375，提交的 token 从 311 变为 13。B=256 的首次分歧有 13 条位于小模型、3 条位于大模型、2 条位于路由判断。路由判断对应的大、小模型策略 logit 差阈值为 0.608068。V2/V1 衡量相同策略下的在线端到端变化，其中包含上述轨迹差异。[逐请求首次分歧、分数和摘要](alignment.json)

## 路由器和复现

模型继续使用 Qwen3-0.6B、Qwen3-8B 和原 GRPO checkpoint。校准得到的配置是 `--router-large-threshold 0.6475`。策略逐 token 计算大模型概率，超过 0.6475 时选用 8B。实际占比随输入和此前生成的轨迹变化。

校准使用与正式实验相同的连续 token ID 生成公式，从 1,000 个可能的起点中按种子 1532 抽取 768 个，每条生成 32 个 token。三次在线生成在阈值 0.63、0.665、0.6475 下分别得到 15.75%、14.07%、14.89%。正式测速前，冻结阈值并在 B=128 引擎上检查两套正式输入，得到 15.60%、15.07%。校准样本与主测输入来自同一个有限序列族，允许重合。早先改变首个 token 的独立样本使阈值 0.70 看似达到 15.18%，但在原始 B=128 输入上只得到 11.93%；该轮归档为试跑。[阈值配置与校准计数](profile.json) · [校准脚本](calibrate.py)

除阈值外，沿用前次的输入、调度参数和软硬件环境。单张 RTX PRO 6000 Blackwell 96 GB、PyTorch 2.9.0+cu128、vLLM 0.12.0、FP16、greedy、CUDA Graph、同步执行。每档重新测量上一版、V1、V2、纯 8B。合成负载一次提交 4B 条固定请求，每请求 128 token 输入、32 token 输出；GSM8K 使用原来 96 道题，每题固定输出 32 token。每组预热一次，正式运行三次，表中为含 prefill 和 decode 的输出 tok/s 中位数。计时组关闭详细 trace，上一版只在 benchmark 侧禁用 writer，保留原采样与校验。两个主测并发均通过实际 decode 行数检查。[各档 token 预算与 KV 池](../grpo-blackwell-batch/report.md) · [本次逐轮结果](measurements.json)
