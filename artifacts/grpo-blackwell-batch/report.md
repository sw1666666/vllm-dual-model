2026-11-26，在同一张 NVIDIA RTX PRO 6000 Blackwell Server Edition 上测试。以 `479d6ff7ac176f508c5b1fabf4e4b79765874b6d` 为基线，B=128 和 B=256 都选 V2。每档 V2 最慢的一轮也快于同档 V1 和纯 8B 最快的一轮。

|---|---:|---:|---:|---:|---:|---:|

| 固定输入 / 256 | 3,156.7 | 3,799.9 | 4,098.3 | 3,642.1 | +941.6 tok/s（+29.83%） | 1.125× |
| GSM8K / 96 | 4,268.9 | — | 5,206.8 | — | +937.9 tok/s（+21.97%） | — |

B=128 时，清理采样热路径贡献 +369.9 tok/s（V1/上一版 **+12.92%**），攒批在此基础上贡献 +231.6 tok/s（V2/V1 **+7.16%**）。B=256 时，两步分别贡献 +643.2 tok/s（**+20.38%**）和 +298.4 tok/s（**+7.85%**）。差值和百分比均用未舍入中位数计算。

## 8B 的执行量

每行取一次正式计时的计数，同组的三次计数相同。8B 占比是使用 8B 的输出 token 数除以总输出 token 数。历史补算沿用原 benchmark 的定义，每次命中累加 `large_delta - 1`；末列再计入预测当前输出的位置。纯 8B 执行连续的原生 KV 路径。

| 数据 / B | 版本 | 8B 输出占比 | 8B 前向次数 | 历史补算位置 | 8B 总执行位置（双模型） |
|---|---|---:|---:|---:|---:|
| 固定 / 128 | 上一版、V1 | 3,609 / 16,384（22.03%） | 131 | 44,475 | 48,084 |
| 固定 / 128 | V2 | 3,616 / 16,384（22.07%） | 117 | 44,468 | 48,084 |
| 固定 / 128 | 纯 8B | 100% | 132 | — | — |
| 固定 / 256 | 上一版、V1 | 7,103 / 32,768（21.68%） | 132 | 87,928 | 95,031 |
| 固定 / 256 | V2 | 7,076 / 32,768（21.59%） | 121 | 87,926 | 95,002 |
| 固定 / 256 | 纯 8B | 100% | 132 | — | — |
| GSM8K / 96 | 上一版、V2 | 98 / 3,072（3.19%） | 6 | 6,991 | 7,089 |

B=128 的 8B 总执行位置完全相同，V2 少调用 14 次；B=256 少调用 11 次，少执行 29 个位置。GSM8K 上两版的 8B 执行量相同，该复核只测了上一版和最终版，不能单独估算攒批在 GSM8K 上的收益。

## 路由与 token 对齐

- **小批验收**。固定 8 条输入、每条 32 个输出位置。上一版、V1、V2 的 256 对路由动作与 token ID 逐请求完全一致。
- **主测 V1**。B=128、256 上，V1 的三次完整输出摘要、8B 命中数、前向次数、历史补算量均与上一版一致。GSM8K 上，V2 与上一版的全部 3,072 个输出 token 也一致。
- **主测 V2**。对两档完整请求集分别独立复跑上一版和 V2，均重现对应正式计时的输出摘要。逐次核对了 8B 实际送入 GPU 的 token ID 与同一请求已提交历史的切片，逐请求核对了 8B KV 游标的连续性。四次复跑均通过。
- **B=128**。512 条请求中有 6 条出现分歧，首次分歧都发生在动作相同的情况下，3 条由小模型、3 条由大模型的 greedy 输出触发。计入后续生成，共有 88 个 token ID 和 11 个路由动作不同。例：请求行 14、输出下标 26，两版都选择 8B。上一版给 token 2038 和 374 的 logits 分别为 30.125 和 30.09375；V2 两者同为 30.078125，greedy 返回 374。
- **B=256**。1,024 条请求中有 18 条至少一个动作或 token 不同，其中 16 条的输出文本 token 序列改变。首次分歧有 7 条来自小模型 logits，6 条来自大模型 logits，5 条来自路由阈值。计入后续生成，共有 264 个 token ID 和 69 个动作不同。例：请求行 407、输出下标 3，在此前相同的动作与 token 历史上，路由的“大模型 logit 减小模型 logit”从 +0.000625 变为 −0.000921，跨过阈值 0；该位置两模型都输出 198。

V2 改变了前向的组批形状。在 FP16 前向中观测到了上述候选排序与阈值翻转。表中 V2/V1 是同策略在线生成的端到端变化，包含实际轨迹变化的影响。两档固定输入上的 8B 占比相差均小于 0.09 个百分点。[诊断样例与输出摘要](alignment.json)

## 实现和计时口径

- 同一 GPU 串行运行各组。vLLM 0.12.0，PyTorch 2.9.0+cu128，`TRITON_ATTN`，CUDA Graph，单卡同步执行，FP16、greedy、阈值 0.5、固定生成 32 个 token，忽略 EOS。模型为 Qwen3-0.6B / 8B，策略为 `grpo_switch_policy_2600.pt`，SHA-256 为 `98707ce5a741bb9692c62a19f76a434b4d72b59e1c2453694e9c38bed5ae04de`。
- 合成输入沿用原公式，每条 128 个 token。每档固定同一组输入，一次 `generate` 提交 4B 条（512 或 1,024），`max_num_seqs=B`，后续请求由调度器补入。GSM8K 一次提交仓库原有的前 96 道题，沿用原 chat template 并关闭 thinking。每组预热一次，随后三次运行完全相同的输入。两档各版本实测的单次 decode 前向行数均达到目标，GSM8K 两版均达到 96。
- 计时从 `llm.generate` 前到返回并同步 GPU 后，包含请求入队、prefill、路由、decode 与输出处理。分子只计输出 token。模型加载、编译、捕图、预热、摘要计算、详细诊断均在正式计时外。所有计时组关闭详细 trace 写入。基线加载从指定提交导出的原始 `vllm_dual`，benchmark 将 writer 的 `write` 替换为空操作，原 sampler、整批重复 argmax、有限值检查、断言、trace 行构造均保留。
- 三个双模型版本共用下表配置。KV 块长 16；每池预留 `B × ceil(max_model_len/16) + 2` 块。纯 8B 使用同一档的 8B KV 预算和公开调度参数。关闭前缀缓存和 chunked prefill，所有轮次都重新计算输入。

| B | 上下文上限 | 公开每步 token 预算 / V2 单次 flush 上限 | 小模型 KV 字节 | 大模型 KV 字节 |
|---:|---:|---:|---:|---:|
| 128 | 160 | 4,096 | 2,352,480,256 | 3,024,617,472 |
| 256 | 160 | 8,192 | 4,701,290,496 | 6,044,516,352 |
| 96 | 256 | 3,072 | 2,822,242,304 | 3,628,597,248 |

V1 在详细校验时才做每个模型的一次整批 argmax 和读回，计时路径保留原 sampler、路由、KV 与 token 更新。V2 的 pending 键为请求 ID 和输出下标。命中 8B 时暂停该请求的下一次 small 前向；其他请求可继续提交。待算 `large_delta` 总和达到 2B、最早入队位置经历第二轮 small（入队当轮计作第一轮）、或已无可运行的 small 工作时，按 FIFO 在预算内分批排空。flush 使用原生 greedy sampler，每个 pending 位置只提交一个 token，历史补算只推进 8B KV 游标。

## 复现

在远端运行以下命令。每次实验使用一个新的输出目录。V1 使用同一命令并省略 `--queue-large`；纯 8B 将模式改成 `large` 并省略该标志。GSM8K 使用 `--batch 96 --workload gsm8k`。

```bash
cd /root/autodl-tmp/vllm-dual-model
source /root/autodl-tmp/envs/vllm-dual-py312/bin/activate
export OMP_NUM_THREADS=8 HF_HUB_OFFLINE=1
python benchmarks/benchmark_grpo_router.py grpo --batch 128 --queue-large \
  --models /root/autodl-tmp/models \
  --checkpoint /root/autodl-tmp/models/grpo_switch_policy_2600.pt \
  --out "artifacts/rerun-b128-$(date +%s)"
```

基线使用同一 benchmark，设置 `DUAL_IMPL_ROOT=/root/autodl-tmp/grpo96-exp/baseline`，省略 `--queue-large`。该目录中的包由 `git archive 479d6ff vllm_dual` 导出。逐轮秒数、tok/s、输入输出摘要、计数与并发实测见[正式计时记录](measurements.json)。完整负载的计时外核查可用 [audit_batch.py](audit_batch.py) 重跑，参数为同一档的 `--models`、`--batch`、`--out` 和对应版本的队列开关。服务器保留各组日志、逐请求审计和原始结果，目录为 `/root/autodl-tmp/grpo96-exp/`。
