# vLLM 双模型改动与 V100 吞吐

截至 2026-11-18，项目已通过 vLLM V1 的自定义调度器和 GPU worker 实现单卡逐 token 路由。并发 16 时，纯大模型达到 987.0 tok/s，双模型在大模型路由概率 0.2～0.8 下达到 251.3～375.7 tok/s。

## 源码改动

- **路由与调度**以请求 ID、输出位置和种子确定每个 token 的路由，支持指定路由序列做回归。lazy 模式可暂缓需要大模型的请求，让其他请求继续解码。达到批量阈值、等待步数上限或所有运行中请求都需要大模型时放行。[路由器](../../vllm_dual/router.py) · [调度器](../../vllm_dual/scheduler.py) · [攒批逻辑](../../vllm_dual/batch_gate.py)
- **模型执行**在同一张卡上加载两个模型，各自维护 KV 缓存并支持 CUDA Graph。小模型处理每个已调度 token。sync 模式同时维护两边的计算进度，用于校验。lazy 模式仅对命中大模型的请求组批，补算缺失的历史 token，再用所选模型的 logits 采样。[Worker](../../vllm_dual/worker.py) · [运行示例](../../examples/offline_inference/dual_model_v100.py)

## 并发 16 的端到端吞吐

单张 V100 32 GiB，Qwen2.5-0.5B-Instruct 与 1.5B-Instruct，FP16、CUDA Graph、贪心解码。每批 16 个请求，每请求输入 128、输出 32 个 token。预热后测 3 次，取每批 512 个输出 token 除以整批生成耗时的均值，计时包含预填充。双模型采用 lazy 模式，攒批阈值和等待上限均为 4，计时包含逐 token 路由日志。

| 运行方式 | 输出吞吐（tok/s） |
| --- | ---: |
| 纯小模型（0.5B） | 1722.5 |
| 纯大模型（1.5B） | 987.0 |
| 双模型，大模型概率 0.2 | 375.7 |
| 双模型，大模型概率 0.4 | 253.6 |
| 双模型，大模型概率 0.6 | 251.3 |
| 双模型，大模型概率 0.8 | 264.9 |

另一次同配置对照中，大模型概率为 0.1 时，开启攒批后吞吐从 406.1 升至 490.4 tok/s（+20.8%）。[基准脚本](../../artifacts/server-v100/benchmark_modes.py) · [各组原始结果](../../artifacts/server-v100/)
